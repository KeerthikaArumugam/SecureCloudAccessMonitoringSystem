Security Event & SOC API

Never put a real API key in source control, screenshots, or logs. Event ingestion requires an active application's X-API-Key; SOC and application read/write APIs require an authenticated administrator session.

Submit an authentication event

POST /api/v1/auth-events — success: 201; validation: 400; missing/invalid key: 401; application mismatch/disabled/revoked: 403; rate limit: 429.

curl -X POST http://127.0.0.1:5000/api/v1/auth-events -H "Content-Type: application/json" -H "X-API-Key: <development-key>" -d '{"application_id":"demo-app","user_id":"demo-user","timestamp":"2026-08-17T10:30:00","ip_address":"192.0.2.10","device_id":"demo-device","browser":"Chrome","os":"Windows","login_success":true,"failed_attempts":0}'

Response fields include event_id, risk_level, threat_score, model_probability, confidence, reasons, alert_created, and incident_id.

SOC APIs

MethodEndpointPurpose

POST/api/v1/soc/incidents/<id>/assignJSON: {"analyst":"admin"}.
POST/api/v1/soc/incidents/<id>/statusJSON: {"status":"TRIAGED","comment":"Reviewed"}.
POST/api/v1/soc/incidents/<id>/notesJSON: {"note":"Investigation started"}; success 201.
GET/api/v1/applicationsDatabase-backed application SOC overview.
GET/api/v1/applications/<application_id>/summaryIsolated events, alerts, incidents, and counts for one application.

Successful list responses use {"items":[], "page":1, "per_page":20, "total":0}. Errors use {"error":"…"} and never include stack traces or secrets.
